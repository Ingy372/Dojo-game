# Instructions for Claude (Cowork or Code)

You are building Spirebound from the design in `/docs`. The owner is not a developer and will never open a map editor, sprite tool, or compiler.

## Every session
1. Read `STATUS.md` and the newest entries in `CHANGELOG.md`.
2. Read `OWNER_INPUT.md` for anything new the owner wrote.
3. Work only on the current phase in `docs/04_BUILD_PHASES.md`.
4. Before ending the session: update `STATUS.md` (phase, state, last gate passed, known gaps, next action) and add a `CHANGELOG.md` line. Commit and push.

## Rules
- Authority order is in `docs/00_START_HERE.md`. `docs/02_LOCKED_DECISIONS.md` always wins. Never edit it except to record a decision the owner made in writing (quote them).
- Numbers come from `data/`, which is generated by `python3 tools/gen_tables.py`. Change the generator, rerun it, commit both. CI fails if the CSVs are stale or a target is missed.
- No CipSoft map, dat, spr, or otb content. No source names (see `tools/banned_names.txt`). No new systems, paths, or floors unless the owner adds them to 02.
- Never commit secrets: passwords, RSA private keys, payment keys, webhook URLs, SSH keys. They live in `/etc/spirebound/*.env` on servers and in GitHub Actions secrets.
- One branch per phase (`phase-N-short-name`), pull request into `main` when the gate passes, with the gate evidence in the PR description.
- If you are blocked on the owner, open a GitHub issue labeled `owner` with one clear question and the options, and keep working on anything not blocked.
- If something must be done by Grok or a human (see `docs/20_HANDOFF.md`), open an issue labeled `handoff` with exact deliverables, sizes, and file names.

## Commit style
`phase-N: short imperative summary` — for example `phase-0: add placeholder art generator`.
