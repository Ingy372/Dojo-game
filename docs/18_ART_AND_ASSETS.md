# Art and assets

No CipSoft graphics anywhere. Every pixel is original: generated procedurally by our scripts, produced by an image model (HANDOFF: Grok), or drawn by a human artist (optional HANDOFF). Placeholders never block phases 0–7.

## Style lock

32 × 32 tiles (64 × 64 for large objects and bosses), Tibia's 3/4 top-down perspective, light from top-left, 1-px dark outline on creatures and items only, limited palette: warm stone, moss green, dull gold, faded red, dark iron, river blue; no neon, no anime screenshots, no text in sprites. Five player silhouettes readable at a glance: shield, greatsword, daggers, bow, focus ring.

## Pipeline

1. `assets/assets.csv` lists every client thing: id, category, flags (ground, blocking, pickupable, stackable, container, etc. — copy flag sets from an existing row of the same category), width, height, frames, png path.
2. Missing PNG → placeholder_art.py writes a flat-color tile with the id printed.
3. HANDOFF images arrive as PNGs at any size. `tools/normalize_art.py` (Cowork): crop, scale to grid with nearest-neighbor, palette-quantize to the style palette, add outline, slice multi-direction sheets.
4. build_assets.py → Spirebound.dat/.spr + items.otb + items.xml. Round-trip test.
5. Asset hash updated in server config.

## Prompts for the image pass

`18b_ART_PROMPTS.md` is generated by Cowork in phase 7 from assets.csv: one prompt per sprite with the style lock prefix, subject, size, direction, and frame count, grouped into batches of ~20. Grok receives batches; returned files are named `<id>.png` or `<lookType>_<dir>_<frame>.png`.
